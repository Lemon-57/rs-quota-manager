- 3 项 Rust 规则测试：通用周限判断、最早到期有效卡选择、恢复观测时间
- 29 项真实插件进程协议场景：RPC v7 握手及旧协议拒绝、management v2 注册、业务 JSON 载荷前缀、挂起/恢复授权、回调结果释放、账号分页、Free 排除、设置版本冲突、自动开关同步、停用状态保留、周限复核、幂等与重启恢复
- 11 项前端契约场景：宿主桥、GET/POST、相对路径、JSON 与错误处理、响应解码、游标编码、原请求标识、CSV 公式转义
- Rustfmt、严格 Clippy、前端类型检查与生产构建通过

## 合同核对

目标宿主为 CPR v3.53.1，提交 `188a6817d141a8d9a1a0bceead4f07477d35276e`。核对范围包含宿主支持清单、SDK 帧与会话合同、management v2、maintenance v1、账号运行投影、额度观测、私有状态，以及 `/api/admin/accounts/reset-credits` 的路由、请求解析和执行入口。

源码固定同一 SDK 提交，清单范围为 `>=3.53.1, <3.54.0`。旧版 RPC v2 宿主不在 v0.1.9 兼容范围内。插件 ID、状态命名空间、schemaVersion 与业务键名不变，升级应沿用原实例。

本插件不声明 scheduler，因此宿主 scheduler v4 的升级不涉及此插件。账号、额度、状态与重置卡调用合同仍适用，业务 Rust 实现无需改写。宿主的临期／按周额度自动用卡与插件设置独立；本次未调用宿主自动用卡配置接口，也未测试两套自动规则同时启用。
