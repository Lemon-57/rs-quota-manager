# v0.1.8 验证说明

## 自动化验证

- 3 项 Rust 规则测试：通用周限判断、最早到期有效卡选择、恢复观测时间
- 29 项真实插件进程协议场景：RPC v7 握手及旧协议拒绝、management v2 注册、业务 JSON 载荷前缀、挂起/恢复授权、回调结果释放、账号分页、Free 排除、设置版本冲突、自动开关同步、停用状态保留、周限复核、幂等与重启恢复
- 11 项前端契约场景：宿主桥、GET/POST、相对路径、JSON 与错误处理、响应解码、游标编码、原请求标识、CSV 公式转义
- Rustfmt、严格 Clippy、前端类型检查与生产构建通过
- Rust 1.99.1、Node 24.22.2、pnpm 11.21.0；Linux 制品使用 Zig 0.15.2 与 cargo-zigbuild 0.21.8 构建
- 同提交官方 CLI 打包，安装包内 6 个文件摘要全部匹配，协议与能力版本满足 CPR v3.43.0 宿主支持清单；从安装包提取的发行二进制通过全部 29 项协议场景
- ELF 依赖的最高 glibc 符号版本为 GLIBC_2.28，保持 Linux x86_64 / glibc 2.28+ 基线

执行方式见根目录 README。协议测试使用本机真实插件进程和模拟宿主，所有卡片消费均为模拟响应，生产请求为零。默认二进制路径按 Linux/Windows 自动选择，也可指定路径：

```bash
node verification/protocol-test.mjs backend/target/debug/quota-manager
```

## 页面验证

使用 UI v0.9.0 的本地模拟页面已检查深色空列表、浅色账号搜索及中文分页。选卡弹窗在未确认时保持消费按钮禁用；浏览器未记录警告或错误。

## 合同核对

目标宿主为 CPR v3.43.0，提交 `402bc37fbb5c83378cc83cec89e9fa251e4a99c1`。核对范围包含宿主支持清单、SDK 帧与会话合同、management v2、maintenance v1、账号运行投影、额度观测、私有状态，以及 `/api/admin/accounts/reset-credits` 的路由、请求解析和执行入口。

源码固定同一 SDK 提交，清单范围为 `>=3.43.0, <3.44.0`。旧版 RPC v2 宿主不在 v0.1.8 兼容范围内。插件 ID、状态命名空间、schemaVersion 与业务键名不变，升级应沿用原实例。
